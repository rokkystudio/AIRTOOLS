# Задание для другой ветки чата: привести README в порядок

Проект: `D:\PROJECTS\ENDOSCOPE`

Цель: переписать `README.md` так, чтобы в нём не были смешаны три разных типа данных:

1. данные, реально полученные на нашем экземпляре устройства;
2. сведения из внешней статьи про похожий Wi-Fi endoscope;
3. предположения, которые ещё требуют проверки.

Итоговый README должен быть компактным и проверяемым, примерно 100-180 строк.

## 0. Обязательный backup

Перед любыми изменениями сделать копию текущего README:

```powershell
$root = 'D:\PROJECTS\ENDOSCOPE'
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
New-Item -ItemType Directory -Force "$root\_backup" | Out-Null
Copy-Item -LiteralPath "$root\README.md" -Destination "$root\_backup\README-before-cleanup-$stamp.md" -Force
```

Не удалять и не перезаписывать без отдельного разрешения:

```text
_backup\
images\
logs\
hashcat\
dumps\
scripts\
```

С файлами, связанными с восстановлением доступа, обращаться особенно осторожно: не менять значения, не нормализовать, не переносить секреты между файлами без необходимости. В README лучше давать ссылку на локальный файл результата, а не размножать секреты по документу.

## 1. Главный принцип

В README должны быть отдельные разделы:

```text
## Проверено на нашем устройстве
## Данные из внешней статьи о похожем устройстве
## Гипотезы / требует проверки
```

Правило:

- подтверждено нашими файлами и логами -> только в `Проверено на нашем устройстве`;
- взято из статьи и не подтверждено локально -> только в `Данные из внешней статьи`;
- вывод по аналогии или предположение -> только в `Гипотезы / требует проверки`.

Не смешивать эти категории в одном абзаце.

## 2. Локальные источники проекта

Использовать как источники проверки:

```text
images\                         фотографии платы
logs\                           UART capture, boot log, shell output
hashcat\                        материалы восстановления доступа
scripts\                        helper BAT для подключения
README.md                       старые заметки, требующие чистки
```

Главные локальные логи:

```text
logs\uart-20260915-200900-57600.txt
logs\uart-shell-20260915-201108.txt
logs\uart-readonly-20260915-201154.txt
```

Не вставлять большие сырые логи в README. Делать краткие выводы и указывать имя файла-источника.

## 3. Что относится к проверенному на нашем устройстве

В этот раздел можно включать только то, что подтверждается локально:

- маркировка платы и дата на плате;
- найденные UART-площадки и параметры UART;
- факт получения shell через UART;
- bootloader, SoC/platform, CPU, RAM;
- модель и размер SPI flash;
- разметка flash из `/proc/mtd`;
- сетевой адрес устройства в AP-режиме;
- SSID и BSSID/MAC;
- реально найденные открытые/закрытые TCP-порты;
- Telnet banner;
- наличие/отсутствие отдельных системных файлов;
- факт восстановления штатного доступа через локальную процедуру;
- расположение helper-скриптов.

Если пункт нельзя подтвердить файлом из проекта, не помещать его в этот раздел.

## 4. Что относится к внешней статье

Ссылки:

```text
https://n8henrie.com/2019/02/reverse-engineering-my-wifi-endoscope-part-1/
https://n8henrie.com/2019/02/reverse-engineering-my-wifi-endoscope-part-2/
```

В README оформить отдельный раздел:

```markdown
## Данные из внешней статьи о похожем устройстве

Источник: Nathan Henrie, reverse engineering похожего Wi-Fi endoscope.

Эти данные использовать только как внешний ориентир. Не считать их подтверждёнными для нашего экземпляра, пока они не проверены локальными логами.
```

Если у статьи и нашего устройства совпадает какой-то признак, написать именно так:

```text
Совпадает с нашим устройством и подтверждено локально: ...
```

Если не проверено:

```text
Указано в статье, на нашем устройстве пока не проверено: ...
```

Данные доступа из статьи не смешивать с актуальными данными нашего устройства. Если они упоминаются, только как историческая попытка или внешний reference.

## 5. Что относится к гипотезам

В `Гипотезы / требует проверки` отправлять всё, что пока не доказано локально:

- точное назначение нестандартного TCP-сервиса;
- внутренняя структура firmware;
- способ сохранения настроек во flash;
- назначение неиспользованных test pads;
- наличие полноценного USB data interface;
- любые выводы, сделанные только по аналогии со статьёй.

Для каждой гипотезы желательно указать способ проверки.

## 6. Рекомендуемая структура README

```markdown
# ENDOSCOPE reverse engineering notes

## Кратко
Что это за устройство и текущее состояние проекта.

## Быстрый доступ
Wi-Fi, IP, порт Telnet, скрипты подключения, где лежит результат восстановления доступа.

## Проверено на нашем устройстве
Короткие bullet points с локальными фактами.

## Подключение
### Wi-Fi
Использовать `scripts\connect-endoscope-wifi.bat`.

### UART
Использовать `scripts\connect-endoscope-uart.bat`.

## Аппаратная часть
PCB, SoC, RAM, flash, UART.

## Flash layout
Краткая таблица из `/proc/mtd`.

## Сетевые сервисы
Только реально проверенные порты и статусы.

## Восстановление доступа
Кратко описать процедуру и где лежат результаты. Не размножать секреты.

## Данные из внешней статьи о похожем устройстве
Отдельный блок, явно помеченный как внешний источник.

## Гипотезы / требует проверки
Неподтверждённое и план проверок.

## Структура каталогов
Кратко описать `images\`, `logs\`, `hashcat\`, `scripts\`, `docs\`, `dumps\`, `_backup\`.

## Следующие шаги
Проверить штатное подключение, сделать полный backup flash, разобрать нестандартный TCP-сервис, не писать во flash до backup.
```

## 7. Что убрать или сократить

Убрать из основного README:

- длинные boot logs;
- повторяющиеся команды;
- устаревшие попытки;
- данные из статьи, если они выглядят как проверенные локально;
- неподтверждённые выводы без пометки `гипотеза`;
- дублирующиеся credential/access-блоки.

Полные материалы должны оставаться в `logs\`, `hashcat\`, `images\`, а README должен быть навигационной картой проекта.


Обновить manifest:

```powershell
$root = 'D:\PROJECTS\ENDOSCOPE'
Get-ChildItem -LiteralPath $root -Recurse -Force |
  Where-Object { -not $_.PSIsContainer } |
  Sort-Object FullName |
  ForEach-Object {
    [pscustomobject]@{
      RelativePath = $_.FullName.Substring($root.Length + 1)
      Bytes = $_.Length
      LastWriteTime = $_.LastWriteTime.ToString('yyyy-MM-dd HH:mm:ss')
    }
  } |
  ConvertTo-Json -Depth 3 |
  Set-Content -Encoding UTF8 "$root\docs\MANIFEST-after-readme-cleanup.json"
```
